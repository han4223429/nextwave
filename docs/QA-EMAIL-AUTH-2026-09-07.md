# 이메일 로그인 추가 — 2026-09-07

## 변경과 권한 경계

Google 동의 화면의 401과 별도로 사용할 수 있도록 Firebase 이메일 링크 로그인, 인증된 계정의 비밀번호 설정, 이메일·비밀번호 로그인을 추가했다. 기존 Google 오류가 해결됐다는 의미는 아니다. 새 경로는 Google 동의 화면을 거치지 않는다.

- 기존 Google 계정은 같은 이메일로 인증한다. 부원 권한을 이메일로 검색하거나 다른 UID로 복사하지 않는다. Firebase가 확정한 UID의 `members/{uid}`만 조회한다.
- 인증된 사용자는 자신의 `updatePassword`로 비밀번호를 추가한다. 별도 계정 생성이나 Google 연결을 교체할 수 있는 비밀번호 재설정 API를 호출하지 않는다.
- 미인증 이메일 세션은 부원 문서 조회·생성 전에 차단한다. Firestore도 `email_verified`가 정확한 boolean `true`인 토큰만 받는다.
- 링크 확인은 명시적 제출로 시작하며 기존 로그인 계정과 이메일이 다르면 계정을 조용히 교체하지 않는다. 처리 중 Google/이메일 중복 제출을 제한한다.
- 일회용 코드가 들어 있는 URL은 메모리에서만 보관하고 주소창에서는 제거한다. 로컬 저장소에는 24시간 동안 편의를 위한 수신 이메일과 시간만 보관할 수 있다. 비밀번호·인증 코드·토큰·원문 오류는 저장하거나 표시하지 않는다.

## 운영 적용 상태

코드 검증과 운영 설정·실제 메일 수신은 구분해서 기록한다. 메일 발송 검증에는 수신자가 본인 주소를 제공하고 발송을 허용해야 한다. Firebase Spark의 이메일 로그인 링크는 하루 5통이므로 최초 인증 후 비밀번호 설정을 제공하며 요금제를 변경하지 않는다. [Firebase 이메일 발송 한도](https://firebase.google.com/docs/auth/limits#email_sending_limits)

- 운영 계정 연결 설정은 실제 콘솔에서 **동일 이메일 계정 연결** 활성화로 확인했다. 현재 Email/Password와 이메일 링크는 비활성화 상태이며 Google은 활성화 상태다.
- 정상 Firebase CLI 계정으로 운영 DB와 현재 게시 규칙을 읽었다. 게시 규칙은 Git `0d2467f:firestore.rules`와 정확히 일치했다. 서버의 예상 밖 변경은 없었다. 게시 규칙 SHA-256: `16aa2ad44e47a9cac324a7960330a0138f2b8e0ee5aa5cbccab229a8a650fdcd`.
- 좁은 명령 `firebase deploy --only firestore:rules --project nextwave-a24e1 --non-interactive`을 실행하려 했으나 **실행 전 자동 승인 검토에서 거절**됐다. 사유는 로그인 기능 추가 승인과 별개로, 지속적인 운영 접근 규칙 변경의 정확한 범위에 대한 명시적 승인이 필요하다는 것이다. 다른 경로로 재시도하지 않았다.
- 규칙 배포 전 이메일 제공업체를 켜지 않았다. 콘솔의 미저장 설정은 취소했고 Google만 활성화된 상태를 다시 확인했다. 운영 규칙 배포와 두 이메일 옵션 활성화를 구체적으로 묶어 사용자에게 승인을 요청했다.
- 실제 메일 발송·수신·운영 계정 로그인은 미검증이다. 수신할 본인 이메일과 1통 발송 허용을 요청했으며, 이 기록 시점까지 메일은 보내지 않았다.
